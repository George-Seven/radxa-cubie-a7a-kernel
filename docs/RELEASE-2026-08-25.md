# Debian 13 for the Radxa Cubie A7A — 2026-08-25

Two images and a full package set, built from a custom Linux 6.6.98 kernel and
verified on hardware. This is the first release where every claim below was
checked on a freshly flashed card rather than on the development board.

---

## Which image

| | |
|---|---|
| **`a7a-standard`** | A76 3.0 GHz · A55 2.8 GHz · DSU 1352 MHz · RAM 2040 MHz |
| **`a7a-maximum`** | the same, plus RAM 2136 MHz and the `a7a-clock` control panel |

Both are a **single file** — no split parts to reassemble — and both grow to
fill your card on first boot. Flash with Etcher, Raspberry Pi Imager or `dd`.

Login is `radxa` / `radxa`, and you are required to change it on first login.

---

## Gigabit ethernet is fixed

The headline fix. Every earlier image, **including Radxa's official ones**, sets
the RGMII transmit delay to the vendor value of `12`, which sits outside the
window the PHY accepts. Frames larger than roughly 250 bytes get corrupted.

What makes it nasty is how healthy it looks: the link reports 1000/full with
zero `tx_errors`, short pings reply, and receive is perfect — but SSH hangs
immediately after key exchange and `apt` stalls. It reproduces across cables.

The corruption is **data-dependent**, so a test payload of constant bytes passes
while real traffic fails. If you are testing this yourself, use random data or
you will conclude a broken board is healthy.

Measured after the fix: **1000 Mb/s full duplex**, sustained.

## 5 GHz wifi works out of the box

`regulatory.db` is now compiled into the kernel via `CONFIG_EXTRA_FIRMWARE`
rather than depending on a userspace package being installed and correctly
ordered at boot. Verified on hardware: country code applied, associated on
channel 44 (5220 MHz) at 80 MHz with Wi-Fi 6 rates — 360 Mbit/s rx, 288 Mbit/s tx.

`a7a-clock` gained a band selector (2.4 / 5 / both) for locking the radio.

---

## Board identity — read this if you make your own images

These images ship with **no SSH host keys** and a blank `machine-id`. Your board
generates its own on first boot.

That is deliberate. An image containing host keys gives every board flashed from
it the *same* SSH identity, so anyone holding the image can impersonate any of
them. Earlier images had this problem. The same sweep removes saved wifi
profiles, bluetooth pairings, `.ssh` directories and shell history.

Expect the usual "authenticity of host can't be established" prompt on your
first connection — that is the mechanism working. If you have connected to that
address before, run `ssh-keygen -R <ip>`.

The build now **fails** rather than warns if any private key or network profile
survives into a finished image.

## Also in this release

- **DSU / L3 is tunable.** The interconnect and shared L3 have their own OPP
  table that is not normally exposed. At 1352 MHz it lifts memory-bound work
  across the board.
- **`a7a-llm` 1.5** — a Stop button that actually interrupts generation, a KV
  cache size estimate before you load a model, and a SearXNG endpoint field with
  a live reachability check.
- **`a7a-clock` 1.6** — DSU, memory controller, NPU and wifi band added; the
  panel scrolls properly in small windows.
- **`a7a-game`** — SuperTuxKart on the GPU. It does not bundle the game; it
  depends on Debian's `supertuxkart` and ships the KMS launcher that gets it off
  software rendering.
- Core dumps are discarded (`core_pattern=|/bin/false`). Unbounded dumps
  previously filled the SD card until the board crashed on a full disk.
- Suspend and hibernation are disabled — neither resumes correctly on this SoC.
- File ownership under `/usr`, `/etc` and `/opt` is `root:root`. Earlier images
  carried build-host UIDs that resolved to no account on the board.
- Every image is built with a full `apt upgrade` applied, and the build verifies
  by hash that the custom kernel was not replaced.

## Measured

Qwen3 4B Q4_0, maximum image, performance governor, 2026-08-24:

| | |
|---|---|
| Prompt processing | **28.06 tok/s** (8 threads) |
| Generation | **4.67 tok/s** (2 threads) |

The two phases want opposite thread counts — generation is memory-bound and 2
threads beat 8 by 36%, prompt processing is compute-bound and 8 beat 2 by 39%.
`a7a-llm` sets both. Full tables in [docs/BENCHMARKS.md](BENCHMARKS.md).

Sustained load, 60 s, all 8 cores: **no throttling**, both clusters held full
clocks, 62 °C rising to **76 °C and still climbing** against an 80 °C passive
trip. Active cooling is not optional at these clocks.

## Honest limits

- **Hardware GL only outside X.** The desktop runs software 2D deliberately —
  glamor on the PowerVR DDK produces cursor trails, and `AccelMethod "none"`
  drops CPU use for the same work from ~60% to 0.6%. `a7a-game` reaches the GPU
  through KMS/GBM.
- **The boot logo has swapped colours.** The R/B fix corrects the GPU desktop;
  the CPU-drawn fbcon inherits the inverse.
- **RAM will not train above 2136 MHz** on this 12 GB silicon.
- **No UFS on SD-boot boards** — `ufshcd_async_scan` fails because the chip is
  not populated.
- **No 3.5 mm audio** — the codec is not populated on the A7A.
- The images are **not GPG-signed** yet. Verify with the published SHA256 sums.
